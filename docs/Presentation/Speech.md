### Речь

> Добрый день, меня зовут Подгорнов Данила Сергеевич, и сегодня я бы хотел рассказать Вам о своей выпускной квалификационной работе на тему: «Разработка рекомендательной системы ранжирования автоматизированных тестов».

~ 15 секунд

## 2. Актуальность

### План

1. Комплексные ИС
2. Множество тестов
3. Время ограничено
4. Необходимость ранжирования
5. Ручное ранжирование
6. Применение LLM

### Речь

> Комплексные информационные системы, продолжительность жизненного цикла которых составляет несколько лет, нуждаются в регулярном регрессионном тестировании. Для тестирования систем такого рода необходимо значительное количество тестов. Время, выделяемое на выполнение тестирования ограниченно и не всегда возможно выполнить все тесты, направленные на проверку необходимого функционала. Чтобы не пропустить важные и нужные тесты, которые необходимо выполнить в первую очередь требуется ранжирование тестов. Ручное ранжирование тестов затруднено, так как это требует учета множества факторов и отнимает значительное количество времени. Поэтому в данной работе предлагается передать анализ метаданных и истории запусков тестов большой языковой модели.

~ 45 секунд

Информация о тестах поступала из системы управления тестами Zephyr Scale, а информация об обнаруженных дефектах из Jira.

## 8. Принцип работы

### План

1. последовательность приоритезации
2. блоки начало и конец
3. что между ними
4. Рассмоттрим группу действий
5. получение информации
6. формирование промпта
7. для каждого атрибута формируется его значимость
8. Записывается в .json
9. Данная группа для каждого отдельного теста
10. формирование ai коэффициента на основе раннее созданных значимостей

### Речь

> На слайде №8 изображена диаграмма последовательности приоритизации. Блок «Начало» соответствует нажатию кнопки «Ранжировать», а блок «Конец» — вывод предлагаемого тестового цикла на экран пользователя. Что происходит между данными действиями? Рассмотрим группу действий. В данной группе сначала происходит получение информации о тесте. Затем формируется промпт и отправляется в локальную LLM. LLM для каждого атрибута теста формирует его значимость - коэффициент ранжирования. Полученная информация записывается в .json-файл. Данная группа дейсвий повторяется для каждого отдельного теста. Затем полученный .json-файл помещается в промпт для формирования AI-коэффициентов. Данный коэффициент формируется на основе раннее заданных коэффициентов ранжирования.

## 9. Демонстрация

### План

1. Результат - предлагаемый цикл
2. Для каждого теста порядок и ai-коэф.
3. Также 8 коэф насколько для данного теста важны эти атрибуты
4. веса - значимость атрибутов, итоговый приоритет - место теста

### Речь

> На слайде представлен результат ранжирования — предлагаемый тестовый цикл. Для каждого теста указан порядок выполнения и AI-коэффициент. Также отображены восемь весовых коэффициентов: насколько для данного теста важны приоритет, статус, метки, число запусков, связанные дефекты, доля падений, последний статус и время выполнения. Веса показывают значимость атрибутов, а итоговый приоритет определяет место теста среди выбранных.

## 10. Схема взаимодействия

### План

1. Упрощенная схема взаимодействия
2. пользователь - браузер
3. Сервер -> локальное хранилище
4. Сервер -> Ollama
5. Сервер -> Zephyr Scale

### Речь

> На слайде под номером 10 представлена упрощенная схема взаимодействия приложения. Согласно данной диаграмме пользователь работает через браузер. Сервер приложения обращается к файловому хранилищу для сохранения артефактов и результатов ранжирования, к локальному сервису Ollama — для запросов к нейросети, и к облачному Zephyr Scale — для получения тест-кейсов и истории запусков.

## 11. Отличительные особенности

### План

1. Отличительной особенностью
2. Система учитывает контекст
3. Сортировка выполняется
4. Дла каждого теста нейросеть формирует

### Речь

> Отличительной особенностью является тесная интегрирация с Zephyr Scale for Jira. Система учитывает контекст связанных с тестом сущностей - дефектов. Сортировка выполняется локальной нейросетью, без передачи данных во внешние облачные сервисы. Для каждого теста нейросеть формирует индивидуальные весовые коэффициенты ранжирования на основании его истории и метаданных.
