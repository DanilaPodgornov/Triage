## Глоссарий

API (аббревиатура от англ. - Application Programming Interface) - интерфейс программирования приложения. Часть приложения, предоставляющая другим системам инструменты для взаимодействия с ней.

QA (аббревиатура от англ. - Quality Assurance - контроль качества) - подразделение сотрудников, занимающихся тестированием и контролем качества информационной системы.

Test run (в переводе с английского - тестовый прогон) - совокупность тестов, объединенных по некоему признаку.

VCS (аббревиатура от англ. - Version Control System) - система, позволяющая просматривать изменения файла, создавать ответвления версий и т.д.

## Введение

С каждым днем современные информационные системы становятся все сложнее и сложнее. Увеличение частоты выхода релизов (новых версий информационной системы), а также добавление новых функций повышают стоимость разработки. С ростом количества новых функций, числа модулей системы и количества интеграций связан и рост количества дефектов. Дефект - это поведение системы, которое отличается от задуманного и противоречит требованиям этой системы. Тестирование программного обеспечения проводится с целью определить такие параметры системы, которые вызывают дефект, чтобы в дальнейшем его устранить. При этом, крайне важно выявлять как можно больше дефектов именно на ранних этапах тестирования.

Для проверки информационной системы на соответствие большого количества функциональных требований разрабатывается огромное количество тестовых сценариев. В условиях ограниченных ресурсов невозможно предусмотреть и выполнить абсолютно все проверки для выявления дефектов. Таким образом, главной проблемой становится грамотное ранжирование тестов, а именно формирование оптимального порядка их выполнения.

Решение данной проблемы – разработка рекомендательной системы ранжирование тестовых сценариев. Это позволит сократить время составления тестовых прогонов, а также позволит выявить большее количество дефектов на ранних этапах тестирования.

## Анализ задания на ВКР

Чаще всего тестированием программного обеспечения занимается специально обученный человек - так называемый QA-инженер. Среди регулярных задач QA-инжеренера можно выделить:

1. Разработка тестов;
2. Актуализация имеющихся тестов;
3. Переодическое наблюдение за инфраструктурой проекта;
4. Поиск и фиксация обнаруженных в системе дефектов;
5. Чтение и анализ технического задания (например, техническое задание на доработку существующей информационной системы);
6. Участие в приемосдаточных испытаниях (ПСИ);
7. Формирование программы и методики испытаний (ПМИ);
8. Документирование проекта.

Для проведения тестирования информационной системы инженеру необходимо сформировать набор тестов, необходимых в данный промежуток времени, а также выполнить данный набор (запустить автотесты, если они разработаны). Тесты, которые войдут в набор отбираются по определенным признакам. Среди этих признаков могут быть:

1. Ориентировочная длительность выполнения теста;
2. Приоритет;
3. Затрагиваемые модули.

Тест кейсы, как правило, находятся в системе отслеживания и управления тестов. С помощью систем данного рода можно планировать тестовые прогоны, а также отслеживать время выполнения тестового набора, каждого отдельного теста, и, даже, отдельного шага внутри конкретного теста. В данной выпускной квалификационной работе речь пойдет про взаимодействие с конкретным инструментом данного класса - Atlassian Zephyr Scale.

Zephyr Scale не обладает внутренним инструментом приоритизации тестов в области одного тестового прогона. В связи с этим тестовому инженеру часто приходится думать, какие тесты выполнять первыми, а какие лучше отложить на потом. Для решения данной проблемы необходимо разработать инструмент позволяющий на основе метаданных теста располагать их в оптимальном, с точки зрения выявления дефектов, в порядке. ==Время - фактор ограничения.==

Отличия
Решение данной проблемы уже Имеют готовый инструменты, однако не один из них не удовлетворяет требованию импортозамещения, а также нарушает цифровой суверенитет.

Разрабатываем информационная система позволит выполнять сортировку тест кейсов а также создавать тестовый прогон посредством API Zephyr Scale.
